        Takedowns

        Detection is step one. Every flagged site has a registrar, and every registrar has an abuse desk that must act on phishing reports. Scamouflage looks up that mailbox over RDAP, writes the report from the evidence it already has, and lets you send it in one click.

        Checking the server…

        How a report is built

        1. Find the abuse desk. The registrar's abuse mailbox comes from the domain's RDAP record (ICANN requires gTLD registrars to publish it). Only rdap.org is contacted, never the scam site.
        2. Assemble the evidence. Registered domain, registrar and IANA id, registration date, certificate SHA-256, issuer, CT log, first-seen time, crt.sh and RDAP links, the model's reasons and score.
        3. Attach proof. The Ed25519-signed alert goes along as JSON with a link to our public key, so the registrar can check nothing was edited.
        4. You decide. Preview the text, add a note, then copy it, open it in your mail app, or send it from the server. Nothing is sent without a click, and only operators on the VM can click: the public address can read everything but trigger nothing.
        5. High bar. Only alerts at or above the extension's blocklist threshold whose registration RDAP confirmed (or that are already on a public scam list) get a button. A false positive is never reported in our name.

        Where to find the button

        Open Latest scams. Every row ends with Report to registrar. After a report goes out the row shows when and to whom it was sent, and the same domain is not reported twice in a day.

        What a registrar can do: put the domain on clientHold or serverHold, which stops it resolving within minutes to hours. That is faster than waiting for browser blocklists to catch up.
